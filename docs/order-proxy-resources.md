# 自动下单、代理与资源管理

## 多条代理

读取设置可保存最多 32 条命名 HTTP / HTTPS / Shadowsocks 代理，以平铺列表直接测试、设为默认或删除。Shadowsocks 可直接选择加密方式并填写服务器 IP／域名、端口和原始密码，由程序自动生成配置；SS 2022 填写服务器提供的 Base64 密钥。也可切换为粘贴分享链接或 HTTP 代理地址。保存代理不会切换出口；保存并设为默认、列表的设为默认都先验证再切换。原有单代理自动迁移，节点密码不回显，也不进入 AI 上下文。

创建或编辑监控时，在读取设置选择独立代理，再选择已有条目即可，无需重复输入凭据。页面分析、元素选择、检测、AI 修复及该监控的下单账户均使用同一出口。独立任务保留选中节点的私有副本；删除列表条目不会改动已有任务或默认连接。要停止使用默认代理，明确点击恢复直接连接。仅改名称、周期等不重复测试未变化且已验证的代理，不重建检测基线。

## 生成脚本与试跑

自动下单附加在对应监控的同一编辑页面，先在下单账户区登录并保存会话，网站验证与二次认证在此完成。保存会话会在新的浏览器中恢复并验证；保存请求可安全重试，暂时缺少登录证据不会删除原会话或误称已经退出。登录窗口按最后一次操作计算闲置期限；保存时单独给予最多 60 秒，避免校验途中被旧闲置计时器关闭。恢复校验只对浏览器关闭或启动超时恢复一次，不重复网站登录。只读账户校验拦截页面后台写入，不会把普通后台 POST 误报为下单；实际提交或付款仍会停止。

自动识别不到已登录状态时，可展开“登录验证设置”，填写同网站的账户页面和仅登录后可见的账户标记。需要后台 POST 才能展示的页面，可以改用直接展示账户信息的页面；未知接口不会自动放行。保存会检查自定义标记在未登录窗口中不存在，恢复时还会核对标记内容。

商品名称和币种可留空，也可通过选择商品手动点选。总价上限必填；试跑核对实际商品、数量、含税费总价与真实币种。商品配置与账单定位代码按用户要求由 AI 根据实际页面生成，提交、付款、结果核对由程序按固定 SOP 执行，没有内置商家脚本。阶段权限、维护入口与验证步骤见 [下单 SOP](order-sop.md)。同一登录会话连续试跑两次，要求商品、数量、金额、币种和付款意图一致，提前发现购物车重复加购。试跑不提交订单或付款。更改商品、要求、AFF、账户、付款方式或触发条件后需重新生成并试跑。

正常触发直接执行预生成脚本，不等待 AI。每份启用配置只执行一次，提交和付款开始前立即保存记录；重启、断线和未知结果不会自动重复下单或扣款。执行后的原订单记录保留，新购买使用新配置。

代码语法、提交前核验及付款结果分别显示。明确缺货会保留配置并等待补货后验证；确定发生在提交前的失败，可恢复后在原配置重新生成和启用。已经提交、付款或结果不明的任务仍需核对原订单，不能重新执行。缺货时可用脱敏页面做离线账单回放，方法见 [下单 SOP](order-sop.md#缺货时的离线账单回放)。

## 付款与 AFF

预选余额、支付宝、PayPal 或其他网站付款方式。核对实际 select / radio 的选项、关联标签和被选中的值，并绑定真实订单、付款 POST 字段；通过中文及外文含义识别方式，不仅根据字段名称猜测。网站方式需先在结算页试跑核实，付款前重新检查总价和币种，选项切换产生新费用也会停止。

余额不足或无法核实可用余额时保留原待付款账单，不改用其他方式。网站实际付款响应跳转至外部收银台时，保留真实收银台链接供扫码、验证，状态为已下单，等待付款。只接受本次受控响应返回的链接，不接受 AI 编造的收银台。未看到真实成功证据时不标记已付款。

选填 AFF 后核对实际推广标识，并检查 Cookie / 表单值确实随订单请求提交；值被替换或缺失会停止。商家最终返佣仍以其规则和记录为准。

页面变化时，提交前可以由 AI 重新生成并连续试跑。订单已经确认创建而付款控件发生结构变化时，只允许 AI 在同一浏览器辅助该订单原账单；辅助不能新建订单、改预算或重新尝试已发出的付款。

## 资源与升级

完成、取消、失败与超时后关闭所属浏览器、代理进程并删除私有临时目录；关闭商品或监控元素选择后删除服务端预览，清理 iframe、图片和取消中的读取。缓存有容量上限且闲置自动到期，隐藏页面暂停轮询，不叠加请求。下单交互、验证和试跑浏览器最多同时两个，为真实触发保留容量，保存会话的恢复校验单独串行，最多一个，下单浏览器总计最多四个；正在退出的浏览器仍占名额，后续操作可以短暂等待退出。监控浏览器读取单独串行排队。Cookie 恢复操作有独立超时；仅在启动或恢复 Cookie 阶段发生浏览器关闭、超时时，在同一次读取的总期限内重建一次。网页读取与跳转失败不会重新提交订单或付款。

新版 compose.yaml 与 compose.build.yaml 在只读容器为 /tmp 挂载 512 MB 上限的 tmpfs，浏览器、缓存和 SS 配置在这里临时写入；账户会话、代理凭据、订单记录仍持久保存在数据卷。内容未变化的存盘跳过磁盘重写，仅保留固定长度摘要进行去重，订单与付款记录仍同步保存。

升级现有编排时同步更新 tmpfs 设置。1Panel 只升级镜像而尚未挂载 /tmp 时，程序兼容使用原数据卷临时目录；更新编排才能获得临时写入的 I/O 改善。tmpfs 使用实际内存，512 MB 是容量上限。

同一账户、相同地址、读取方式及出口的重叠网页请求共用当次读取，避免重复启动 Chrome 和代理；读取结束后立即释放，下一次检查仍读取新内容，不延长监控周期。取消一个预览不会中断仍在读取的监控，所有使用者取消后才中止底层请求。页面分析复用浏览器已取得且能提取候选的真实接口响应，其余接口仍实际探测。

普通监控的检测结果、日志、错误与下次执行时间在检查结束时一次保存；订单、付款和通知队列仍即时持久化。空通知队列直接跳过，缓存统一负责过期与容量限制，减少重复扫描。

前端状态未变化时返回空的 304 响应，只更新相对时间，不重建任务、活动和日志列表；状态变化时只重建内容变化的列表。页面隐藏或退出时取消进行中的状态请求。真实浏览器联调验证六次重叠网页读取仅启动一次 Chrome，后续检查重新读取，结束后无遗留浏览器进程、私有临时目录或代理。

## 负载诊断

在负载升高时打开问题容器的终端，运行：

```bash
npm run diagnostics
```

直接运行 Node 的 Linux 主机也可运行此命令。诊断一次性采样，区分宿主 load / CPU 与当前容器，读取 [Linux PSI](https://docs.kernel.org/accounting/psi.html)、D 状态线程及等待位置、换页和 CPU 限额，不输出环境变量或进程参数，也不建立常驻监控。Chrome 启动时的短暂进程活动与持续磁盘、内存等待需结合现场数据区分；仅凭 CPU 正常、load 高不能确定服务器具体瓶颈。

自动化联调使用本地模拟商家验证提交、付款、AFF、异常和一单限制，不购买真实商品。Windows 上验证浏览器释放，持续集成另外验证只读 Linux 镜像、tmpfs 和真实加密 Shadowsocks 流量。
